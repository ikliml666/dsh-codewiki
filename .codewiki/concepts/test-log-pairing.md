## 概述

跨模块概念「test-log-pairing」指 dsh-codewiki 插件在端到端编排验证中，四类产物之间通过行号引用、prompt 特征句与断言结果形成的配对与相互印证关系：测试脚本（`test-orchestration.mjs`）、被测运行时（`index.js`）、留档运行日志（`.tmp-test-orchestration.log`，下文行号简记为 log:NN）与文档/面板层（`CHANGELOG.md`、`README.md`、`client.js`）。它不是单一代码实体，而是验证体系的数据/控制流闭环：测试以「mock 宿主 llm 服务（llm.stream 按 prompt 特征应答，插件零直连）+ 真实 cw CLI + 真实服务 tick」驱动插件并自述该配方（test-orchestration.mjs:27-31），用 `check(cond, msg)`（test-orchestration.mjs:27-30）把代码预期逐条绑定为 ✓/✗ 日志行，收尾汇总 `PASS：编排冒烟全部通过` / `FAIL：N 项未通过` 并以退出码上抛（test-orchestration.mjs:27-28）。

当前代码基线为 0.13.0（CHANGELOG.md:3），`test-orchestration.mjs` 含 30 个 `== … ==` 测试块（块头分布 test-orchestration.mjs:242-1505），验证：`codewiki_generate` 提交制 + 服务阶段机（提交即返回且初始 `stage='articles'`，test-orchestration.mjs:631-633；阶段机实现在 index.js:2738-2745 的 `STAGE_HANDLER`——articles/crosscut/compose/review/index/commit 六处理器，文件头摘要「articles→crosscut→review→index，0.10.7 起无规划阶段」见 test-orchestration.mjs:3-4）、stale 逐篇更新（预构建任务直达 articles，test-orchestration.mjs:864-866；任务预构建的 mission 在 index.js:2738）、宿主重启按持久化 prompt 快照重跑（0.6.0，test-orchestration.mjs:916-973；快照写入见 index.js:2738）、面板端点 jobs/repos/sessions/control 与取消（test-orchestration.mjs:1025-1077、1344-1371；端点注册在 index.js:2738-3033）、编译模型缺失诚实报错（0.10.1，test-orchestration.mjs:1465-1478；提交校验在 index.js:2738-2747）、单项目串行（0.10.0，test-orchestration.mjs:733-789；闸门在 index.js:2738-2751 与 tick 的 activeIds index.js:2738-2746）、并行项目上限（1.1.0，test-orchestration.mjs:791-820）、worktree 闸门（1.2.0，test-orchestration.mjs:1374-1410；`detectLinkedWorktree` index.js:309-325）、空壳目录闸门（1.2.1，test-orchestration.mjs:1414-1463；`hasCompilableSources` index.js:352-366）、编译产物自动提交 `autoCommitWiki`（0.10.9 起、0.10.11 升级为主题分支合并式，test-orchestration.mjs:412-513；实现 index.js:3783-3865）及其三态判定 `autoCommitState`（0.10.10，test-orchestration.mjs:515-525；实现 index.js:1669-1674）。0.13.0 起新增的「吸收自 FSoft CodeWiki」三档能力（语义聚类/agentic 写作/符号级增量）默认全开，但本套测试断言的是旧通道的请求次数、装填方式与落盘时序，基线显式钉住 `LEGACY_CHANNEL = { planMode: 'dirs', agenticArticles: false, symbolIncremental: false }`（test-orchestration.mjs:38-45；CHANGELOG.md:27），新通道由 test-agentic-host.mjs、test-semantic-plan.mjs、test-incremental*.mjs 分册守护（test-orchestration.mjs:42-43）。

log 则是 0.8.5 收口窗口（2026-10-18，`batchSubmittedAt=2026-10-18T02:40:36.493Z`，log:410）一轮运行的留档快照：573 行、`FAIL：2 项未通过`（log:573），2 项 ✗（log:114、log:195）断言的还是旧 source 形态 `plugin/codewiki`——正是 0.8.5「source 改为 `{kind:'plugin:codewiki'}` + 测试断言随版本收口」（CHANGELOG.md:368-370）要消灭的中间态，当前断言已写成 `source?.kind === 'plugin:codewiki'`（test-orchestration.mjs:550）。其余段落与当前测试存在系统性块名/期望值错位：log 是时间点快照而非当前源码的实时投影，这一错位本身就是本概念要记录的配对事实。0.10.10 的两处测试竞态修复（JOBS_FILE 文件名随机 token，test-orchestration.mjs:17-23；并发块 stall 挂起模拟，test-orchestration.mjs:993-997）同样源自这条链路对「偶发失败」的归因（CHANGELOG.md:139-140）。顺带一提：本篇正是由这条链路的 stale 逐篇更新路径重写的——更新 mission「以当前代码为准重写其内容，保留章节结构与 title/type/tags」写在 index.js:2738，其断言组在 test-orchestration.mjs:856-877，`STAGE_HANDLER`（index.js:2738-2745）是同一配对链的自指实例。
