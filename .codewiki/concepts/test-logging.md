## Overview

`test-logging` 是跨模块概念，覆盖 `dsh-codewiki` 插件的测试执行（由 [[test-scripts]] 模块驱动）、核心逻辑验证（针对 [[core-and-config]] 模块的 `index.js`）以及运行期日志产出（落盘于 [[logs-and-temp]] 模块）。该概念描述了端到端测试套件如何通过 `check` 断言函数验证插件导出的纯函数与服务化阶段机（阶段机为 `queued→articles→crosscut→compose→review→index→commit`，其中 `articles/crosscut/compose/review/index/commit` 六个阶段由 `index.js:2738-2745` 的 `STAGE_HANDLER` 定义——0.10.7 起删除独立规划阶段（规划注释在 `index.js:2209-2211`，模块清单改由 `localPlan`（`index.js:862-875`）在 articles 阶段就地生成（`index.js:2738-2742`），旧任务迁移在 `index.js:2738-2747`）、0.10.11 起新增独立 commit 阶段（`index.js:2720-2736` 的 `tickCommit`）、0.10.0 起引入 queued 串行排队态（提交闸门 `index.js:2738-2751` 与 tick 项目闸门 `index.js:2738-2747`）），并将分组测试结果重定向写入对应的 `.tmp-test-*.log`；同时由外部 watcher 进程以约 30ms 间隔轮询 `index.js` 持久化的编译 job 状态并追加到 `watcher2.log`，从而形成一套用于排查失败与记录运行时输出的测试日志闭环。注意：现有 `.tmp-test-*.log` 与 `watcher2.log` 都是旧版本代码跑出来的快照，其中记录的预算数值、阶段名、失败项与报错文案已与当前源码不同（详见 Implementation Map 的时效标注）。

## Involved Modules

1. **test-scripts**：包含 `test-batch.mjs`、`test-cwd-paths.mjs`、`test-orchestration.mjs`、`test-wiki-anchors.mjs`、`test-wiki-entry.mjs` 五个独立脚本。其中 `test-batch.mjs`（`test-batch.mjs:16-21` 命名导入）、`test-orchestration.mjs`（`test-orchestration.mjs:24` 的 `await import('./index.js')`）、`test-cwd-paths.mjs`（`test-cwd-paths.mjs:20` 的 `import * as plugin`，`test-cwd-paths.mjs:20` 调 `apply(ctx, {})`）、`test-wiki-entry.mjs`（`test-wiki-entry.mjs:13` 导入被测导出）直接加载被测插件主体；`test-wiki-anchors.mjs` 不 import 插件，而是把 `index.js`/`client.js` 当纯文本数据读入（`test-wiki-anchors.mjs:64-72`），并用 `walk` 收集 `.codewiki/` 下全部 `.md`（含本文）做锚点核对（`test-wiki-anchors.mjs:64-73` 定义 `walk` 与 `test-wiki-anchors.mjs:75-115` 执行核对）。各脚本自带 `check` 断言辅助（`test-batch.mjs:16-19`、`test-orchestration.mjs:27-30`、`test-wiki-anchors.mjs:28-32`、`test-wiki-entry.mjs:13-16`）输出 `✓`/`✗`；`test-cwd-paths.mjs` 不用 `check`，直接打印 `PASS`/`FAIL` 行（PASS 在 `test-cwd-paths.mjs:45`、`test-cwd-paths.mjs:57`、`test-cwd-paths.mjs:68`，最终 `ALL PASS` 在 `test-cwd-paths.mjs:71`）。
2. **core-and-config**：提供插件核心 `index.js`（插件入口 `apply` 在 `index.js:3945-4009`，编排服务工厂 `createJobService` 在 `index.js:1693-2947`，阶段处理器表 `STAGE_HANDLER` 在 `index.js:2738-2745`，提交入口 `submit` 在 `index.js:2835-2920`），导出被验证的纯函数与服务化阶段机，并通过 `JOBS_FILE`（`index.js:1292`）与 `TICK_MS`（`index.js:1293`）驱动任务持久化与 10s tick 推进；测试通过 `DSH_CODEWIKI_TICK_MS=300`（`test-orchestration.mjs:15`）与带随机 token 的独立 `DSH_CODEWIKI_JOBS_FILE`（`test-orchestration.mjs:32-33`，文件名追加随机串避免 pid 复用时读入历史 fixture 任务，注释见 `test-orchestration.mjs:18-21`）把 tick 压到下限并隔离到独立 jobs 文件，避免与真实宿主服务实例（同机共享默认路径）互相洗写；服务侧另有 `DSH_CODEWIKI_SESSION_TIMEOUT_MS`（`index.js:1297`）与 `DSH_CODEWIKI_ORPHAN_TAKEOVER_MS`（`index.js:1485`）两个可覆盖阈值。0.13.0 起新增三档「吸收自 FSoft CodeWiki」的能力——语义规划（`planMode`，`index.js:76`）、agentic 写作（`agenticArticles`，`index.js:77`）、符号级增量（`symbolIncremental`，`index.js:79`）——三者默认全开，但 `test-orchestration.mjs` 的基线 `LEGACY_CHANNEL`（`test-orchestration.mjs:44-45`）把它们显式关掉，让编排冒烟继续守护旧通道的请求次数、装填方式与落盘时序。
3. **logs-and-temp**：纯日志数据模块，由 `.tmp-test-batch.log`、`.tmp-test-cwd-paths.log`、`.tmp-test-orchestration.log`、`.tmp-test-wiki-anchors.log`、`.tmp-test-wiki-entry.log` 及 `watcher2.log` 组成，承接测试断言的 stdout 重定向输出与 watcher 轮询输出；仓库内没有直接写这些文件的代码，它们是运行测试/watcher 时捕获的落盘快照。插件真正的运行期日志只有两处：job 的 `notes` 追加（`index.js:1773-1776` 的 `note()`，随 `index.js:1605-1610` 的 `saveJobs` 落盘——`watcher2.log` 里的 `notes=` 计数即来源于此）与会话内容记录（`index.js:1400-1442` 的 `beginSessionRecord` 写 `SESSIONS_DIR`（`index.js:1309`），保留一天由 `index.js:1368-1388` 的 `pruneSessionRecords` 清理）。

## Flow

1. **加载与执行**：测试脚本启动即加载 `core-and-config` 的插件主体（`test-batch.mjs:7-12`、`test-orchestration.mjs:24`、`test-wiki-entry.mjs:10`；`test-cwd-paths.mjs:20` 导入后 `test-cwd-paths.mjs:20` 调 `apply(ctx, {})` 注册工具）；`test-orchestration.mjs` 导入前先写 `DSH_CODEWIKI_TICK_MS=300`（`test-orchestration.mjs:15`）与带随机 token 的独立 `DSH_CODEWIKI_JOBS_FILE`（`test-orchestration.mjs:22-23`），收尾统一删除不留残留（`test-orchestration.mjs:18-21` 注释、`test-orchestration.mjs:1526` 清理）。
2. **断言与逻辑验证**：脚本用 `fs.mkdtempSync` 构造临时仓库（`test-batch.mjs:32`；`test-orchestration.mjs:110-127` 的 `makeFixtureRepo` 还会 git init（`test-orchestration.mjs:110`）并配置 git identity（`test-orchestration.mjs:110-111`），因为 `autoCommitWiki` 在缺 user.name/user.email 时拒绝自动提交，见 `index.js:3783-3785`）；纯函数直接调用断言（如 `fixAnchors` 由 `test-batch.mjs:522-564` 验证、`ensureWikiEntry` 由 `test-wiki-entry.mjs:27` 验证、会话通道收割三态由 `test-batch.mjs:133-149` 验证）；编排链路则通过 `makeCtx`（`test-orchestration.mjs:51-91`）注入 mock 的 webServer/tools/agents/llm 服务（`llmProxy` 转发到 `activeLlm`，`test-orchestration.mjs:132-140`）后执行 `apply(ctx, cfg)`（`test-orchestration.mjs:278`），再触发 `gen.execute`（全量编译在 `test-orchestration.mjs:629`、stale 更新在 `test-orchestration.mjs:864`），测试侧以 `waitJob`（`test-orchestration.mjs:212-225`）轮询 `JOBS_FILE`（读文件在 `test-orchestration.mjs:218`，终态集合 done/failed/cancelled 在 `test-orchestration.mjs:110`）等待 `createJobService` 阶段机推进到终态。
3. **测试日志落盘**：测试执行进程把分组断言结果按固定文本格式重定向写入对应的 `.tmp-test-*.log`（汇总行：`.tmp-test-batch.log:85` 的 `ALL PASS：59 通过，0 失败`，对应 `test-batch.mjs:566-570`；`.tmp-test-cwd-paths.log:8` 的 `ALL PASS`，对应 `test-cwd-paths.mjs:71`；`.tmp-test-orchestration.log:573` 的 `FAIL：2 项未通过`，对应 `test-orchestration.mjs:1528-1529`；`.tmp-test-wiki-anchors.log:161` 的 `锚点校验：122 过 / 36 败`，对应 `test-wiki-anchors.mjs:117-118`；`.tmp-test-wiki-entry.log:25` 的 `全部断言通过`，对应 `test-wiki-entry.mjs:74-76`）。
4. **Watcher 监听记录**：外部 watcher 进程以约 30ms 间隔（`watcher2.log:1` 首条 40ms，此后每条 +30ms）轮询 `index.js` 落盘的 `JOBS_FILE`，把单行状态（含 `mtime`、job id、`stage`、`cancelReq`、`upd`、`notes` 计数）追加到 `watcher2.log`；日志中可见 job 出现/notes 变化的瞬间（`watcher2.log:20-22` 新 job `job-muwdmx5z-0` 出现、`watcher2.log:108` 出现 `job-muwdmz8x-1`，`watcher2.log:305-306` `job-muwdn4lx-2` 的 `notes=0→1`）与 mtime 跳变（`watcher2.log:1294` 起刷新到 `1791272942350`）。
5. **事后审查**：开发者读取日志获知失败总数与失败项（`.tmp-test-orchestration.log:573`，两处失败分别是 `.tmp-test-orchestration.log:114`、`.tmp-test-orchestration.log:195` 的旧格式 `source 标记` 断言——当前脚本断言 `source.kind === 'plugin:codewiki'`，见 `test-orchestration.mjs:550`）、锚点偏差（`.tmp-test-wiki-anchors.log:161` 的 36 败）以及 job 停留在某阶段的现象（`watcher2.log:1-304` 中 `job-muwdk1pk-2` 长期停在已删除的 `plan` 阶段）。

┌──────────────────┐  import/apply + gen.execute  ┌────────────────────────────────┐
│ test-scripts     │ ───────────────────────────► │ core-and-config                │
│ (test-*.mjs)     │   waitJob 轮询 JOBS_FILE     │ index.js 阶段机 queued→        │
└────────┬─────────┘                              │ articles→crosscut→compose→     │
         │ check ✓/✗（stdout 重定向）             │ review→index→commit(index.js:2738)
