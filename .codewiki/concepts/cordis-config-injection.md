## Overview

`cordis-config-injection` 是 dsh-codewiki 插件在 DeepSeek Harness（cordis 框架）中运转的核心机制，覆盖两件事。其一是通过 `ctx.inject(['service'])` 严格获取宿主服务切片——宿主侧注入 `agents`/`llm`（index.js:4114-4115）、`tools`（index.js:3583）、`workspaceRegistry`（index.js:3610）/`webServer`（index.js:4060），客户端注入 `slots`/`locale`/`configForms`（client.js:6）——并遵循 cordis 严格语义：未 inject 直接访问服务属性即抛错，`typeof` 守卫无效（0.2.7 曾因此整体未装载，CHANGELOG.md:856-858）。其二是配置的注入与热生效：schemastery `Config` 全字段 `.volatile()`（index.js:92-118），运行时经 `liveConfig` 每次调用重新解包并钳制（index.js:4060-4102），客户端经 `configForms.mutate` 单层 op + revision CAS 写回（client.js:797），与 patch 文件手改等价（README.md:45）。

模型通道自 0.10.1 起唯一化为宿主 `llm` 服务——内置百炼直连与 `credentials` 凭证解析链已删，`batchProvider` 留空即提交失败、插件不保存任何密钥（CHANGELOG.md:201-207）。产物提交链自 0.10.9-0.10.11 收敛为：`autoCommitWiki`（index.js:1750-1832）→ `autoCommitState` 三态判定（index.js:3946-3951）→ 独立 `commit` 阶段「主题分支 `codewiki/wiki-<jobId>` 提交 → 合并回原分支」（index.js:73-89、index.js:73-107）。0.11.0 新增 `parallelProjects` 并行推进上限（index.js:2884，派生 `parallelLimit` index.js:2884-2888）、queueAhead 排队可见性（index.js:2884-2895）与编译会话记录（index.js:2884-3026）；1.2.0 加入 worktree 闸门（index.js:3906-3913）与全局会话 Tab（client.js:1622-1632）；1.2.1 加入空壳目录统一判定 `isDeadCompileTarget`（index.js:95-103）；0.12.2 加入 `bigConcurrency` 大档独立并发（index.js:95、index.js:95-154）。

0.13.0 吸收 FSoft-AI4Code/CodeWiki 三层能力并把它们全部接进本概念：新增 `planMode`/`agenticArticles`/`agenticMaxSteps`/`symbolIncremental` 四个配置（index.js:79-82，默认全开，CHANGELOG.md:109），引入 `lib/symbols.js`/`lib/cluster.js`/`lib/graph-diff.js`/`lib/incremental.js`/`lib/articles-agentic.js`/`lib/agentic.js` 六模块（index.js:963-971）；规划面新增 `semanticPlan` AST 符号聚类（index.js:2161-2244）由 `buildPlan` 按 `planMode` 分派、失败退回 `localPlan`（index.js:2110-2133）；写作面新增 `startAgenticRun` 执行器与单轮通道并列（index.js:934-981），失败严格过半由 `shouldFallBackFromAgentic`（index.js:2019-2024）/`shouldFallBackHere`（index.js:2019-2026）退回单轮重跑一次（index.js:1984-2022）；`tally` 的去重语义在 0.13.2 收窄为 `replace`/`mergeByName` 两个独立开关（index.js:1978-1987，CHANGELOG.md:109）。0.13.2 另把 agentic 通道接进双池——`markBigAgenticTasks` 按模块源文本量打 `bigTier` 标记（index.js:810、index.js:810-821，CHANGELOG.md:109）；0.13.3 修复 agentic 真实运行暴露的 `read_code` 重复读与 MessageId 漂移（CHANGELOG.md:9-12）。编排测试用 `LEGACY_CHANNEL` 钉住旧通道（test-orchestration.mjs:44），新通道由独立测试文件守护（CHANGELOG.md:59）。该概念横跨测试验证（test-orchestration.mjs）、文档（README.md、CodeWiki.md、CHANGELOG.md）与宿主/客户端实现（index.js、client.js、package.json），是插件装配、模型通道声明与设置持久化的基石。

## Key Components

### 配置 Schema 与热生效（index.js）

- `Config` (index.js:60-86)：schemastery `z.object`，全部字段 `.volatile()`（execute/tick 时解包读取，改完即生效）。字段与默认值：
  - `enabled` (index.js:61，默认 true，停用后工具立即报错)
  - `binaryPath` (index.js:62，留空 PATH 优先、捆绑 `bin/cw` 兜底)
  - `batchProvider` (index.js:6，默认 `workbuddy`；必须是模型设置里已注册的 provider id，留空无法提交——0.10.1 起唯一通道)
  - `batchModel` (index.js:6，默认 `hy3`)
  - `batchReasoningEffort` (index.js:65，留空=模型默认档；可选值由 `/api/codewiki/model-efforts` 从模型目录实时读取)
  - `bigProvider` (index.js:66，默认 `volces-ark`，留空=关闭大档、退回会话通道兜底)
  - `bigModel` (index.js:67，默认 `glm-5.3-flash`，512k 上下文)
  - `bigReasoningEffort` (index.js:69) / `bigTokenBudget` (index.js:69，默认 420000)
  - `sessionTier` (index.js:70，仅大档装不下且关闭大档时兜底的子智能体档位 id)
  - `maxConcurrency` (index.js:71，默认 2，1–8 硬顶 8)
  - `bigConcurrency` (index.js:95，默认 0；1–8 硬顶 8，0=跟随默认档并发——大档与默认档两池各自独立限流、同时推进，总在飞=两者之和，0.12.2)
  - `serialProjects` (index.js:73，单项目串行，默认开)
  - `parallelProjects` (index.js:73，默认 2，1–4；关闭单项目串行后生效——0.11.0 新增)
  - `articleLanguage` (index.js:75，默认中文)
  - `planMode` (index.js:3154，0.13.0：`auto`=AST 符号提取+LLM 语义聚类、失败自动降级目录分组；`dirs`=只按顶层目录分组旧行为)
  - `agenticArticles` (index.js:77，0.13.0 默认开：模型自己 `read_code`/`list_files`/`edit_article` 增量写作，关闭走单轮整包装填旧通道)
  - `agenticMaxSteps` (index.js:78，0.13.0 默认 30，硬顶 100：agentic 单篇工具调用轮次上限)
  - `symbolIncremental` (index.js:79，0.13.0 默认开：stale 增量按 AST 符号级判定变更，关闭按文件级 mtime/hash)
  - `updateReminder` (index.js:81，默认开) / `autoCommit` (index.js:81，默认开：插件在主题分支提交产物再合并回原分支，只 add `.codewiki/` 与 `CodeWiki.md`；失败降级为提醒会话模型提交)
  - `excludePaths` (index.js:83) / `autoUpdate` (index.js:84，默认关) / `autoUpdateMin` (index.js:85，默认 30 最小 5) / `workspaceOnly` (index.js:85，默认开)
- `val(x)` (index.js:88-90)：兼容 schemastery 对象的 `.get()` 与裸值。
- `liveConfig(config)` (index.js:63-105)：每次调用重新解包并钳制——`batchProvider` 不做任何回落 (index.js:63)，空值由 submit 校验拦截；`batchModel` 空回落 `hy3` (index.js:67)、`bigModel` 空回落 `glm-5.3-flash` (index.js:69)、`bigTokenBudget` 下限 `BATCH_TOKEN_BUDGET` (index.js:71)、`maxConcurrency` 仅 ≥1 时钳到硬顶 8 否则默认 2 (index.js:95-97)、`bigConcurrency` ≥1 时钳 8 否则 0=跟随默认档 (index.js:73-75)、`serialProjects` 显式 false 才关 (index.js:2884)、`parallelLimit` 派生——串行时恒为 1，否则 `clamp(round(parallelProjects),1..4)` 默认 2 (index.js:76-80)、`planMode` 白名单 `auto`/`dirs` (index.js:77)、`agenticArticles` 显式 false 才关 (index.js:78)、`agenticMaxSteps` 钳 1–100 (index.js:79-82)、`symbolIncremental` (index.js:84)、`autoUpdateMin` 下限 5 (index.js:81)、`autoCommit`/`workspaceOnly` 均为「显式 false 才关」 (index.js:85、index.js:85)。

### 宿主侧 cordis 注入入口（index.js）

- `apply(ctx, config)` (index.js:4068-4132)：cordis 插件入口，装配顺序：
  1. `ctx.inject(['agents'])` → 模块级 `agentsRef`（声明 index.js:1737）
  2. `ctx.inject(['llm'])` → 模块级 `llmRef`（声明 index.js:1742；0.8.6 引入，`hostCtxRef?.llm` 在严格 cordis 下访问即抛，CHANGELOG.md:429-430）
  3. `createJobService(config, wakeCompileSession)` + `service.start()` (index.js:4072-4073)
  4. `ctx.effect(() => () => service.stop())`——必须返回 disposer 本身；写成 `() => service.stop()` 会在启动时当场停服 (index.js:4075，0.4.3 教训 CHANGELOG.md:691)
  5. 构建 `generateDef`/`updateDef` (index.js:4077-4078)
  6. 自动更新调度：`schedState` (index.js:4082) + `autoScan` 60s 心跳（index.js:4082-4109，对历史工作区逐仓 scope=auto，execute 幂等；排除项跳过 index.js:373、worktree 路径经 `isWorktreeCwd` 静默跳过 index.js:392、空壳目录经 `hasCompilableSources` 静默跳过 index.js:4105，单仓异常只记 `schedState.lastError` index.js:4110-4111）；`scanTimer` (index.js:4110-4112)
  7. `ctx.inject(['tools'])` 注册四个工具——`cw`/`codewiki_generate`/`codewiki_update`/`codewiki_progress` (index.js:7-23，清单 index.js:7)
  8. `installWebServer(ctx, service, {config, schedState, compile})` (index.js:3578)
  9. `installUpdateReminder(ctx, config)` (index.js:4034)
- 工具注册逐定义 try/catch (index.js:4119-4129)：单个 schema 违规只丢该工具并 console.error，不让回调失败触发 cordis 回滚整个 fiber（0.8.2 教训：type 数组致 4 工具全消失，CHANGELOG.md:472-480）。
- `createJobService(config, onSettled)` (index.js:1774-3070)：返回 `{submit, cancel, list, findActive, start, stop}` (index.js:1774)。与配置/注入直接相关的面：

  - `settleJob` (index.js:1914-1944)：0.13.0 起 agentic 任务没有 `batchPrompt` 快照，重跑依据是 `t.agentic === true && t.mission && t.articlePath`（index.js:805-813）；单轮任务仍按持久化 `batchPrompt` 快照重跑（index.js:1923-1932）；两者都不可用则 fail（index.js:805）。

## Data Flow

1. **配置加载与注入**：宿主按 profile patch `config:` 段（挂载条目见 README.md:66-71）构建 schemastery 配置对象，以 `apply(ctx, config)` 注入插件；全部字段 `.volatile()`，允许改完即生效。
2. **服务切片装配**：`apply` 先缓存 `agentsRef`/`llmRef` (index.js:4114-4115)，再经 `tools` 服务注册四个工具 (index.js:3578-3594)；`installWebServer` 内注入 `workspaceRegistry` (index.js:3610-3613) 与 `webServer` (index.js:4034)；`installUpdateReminder` 经 `agent.ctx.inject(['systemPrompt'])` 注册 section (index.js:4068-4082)；客户端 inject `slots`/`locale`/`configForms` (client.js:6)。
3. **严格语义保障**：未 inject 的服务属性访问即抛（测试用 getter 模拟真实 cordis，test-orchestration.mjs:1494-1496）；插件侧两道防御——`apply` 自身不向 cordis 抛错、已注册工具不被回滚 (test-orchestration.mjs:1499-1501)，工具注册循环逐定义 try/catch (index.js:4068-4078)。
4. **配置热读取与持久化闭环**：客户端订阅快照 (client.js:764-781) → `save()` 25 键 diff (client.js:797-803) → `form.mutate(ops, revision)` CAS 写回宿主 configForms (client.js:92) → 下次 execute/tick `liveConfig` 重新解包 (index.js:92-134)。面板排除清单走同一条 mutate 链路 (client.js:92-110)。
5. **模型通道与自动提交（0.10.11 独立 commit 阶段）**：submit 三重校验（provider/model/llm.stream，index.js:452-461）→ 全部环节走 `llmChat`→宿主 `llm.stream` (index.js:454-479，凭证由宿主按 provider 解析，插件零密钥)，`runRealtimeTasks` 按 `bigTier` 分池限流 (index.js:2774-2833) → `tickIndex` 收尾后有产物且 `autoCommit` 开启则 `setStage('commit')` 提前返回 (index.js:2843-2845) → 下一 tick `tickCommit` 调 `autoCommitWiki` 走「主题分支 `codewiki/wiki-<jobId>` 提交 → 合并回原分支 → 删主题分支」（index.js:1723-1739、index.js:1723-1805）→ 结果写 `job.autoCommit`（含 `mode`/`branch`/`fallback`，schema index.js:1750-1764）→ `autoCommitState` 判 `committed`/`no-changes` 时 `wakeCompileSession` 直接 return 零唤醒 (index.js:1710)；`pending` 时才经 `commitHintText` (index.js:3990-4021) 与 steer 发一次性「产物待提交」提醒并带失败原因。
6. **0.13.0 规划与写作双通道**：full 编译进 articles 时 `scanRepoFiles` → `buildPlan` (index.js:2161-2165、index.js:963-986)——`planMode=auto` 走 `semanticPlan`（AST 符号提取 + 语义聚类，index.js:941-1024），失败退回 `localPlan` 顶层目录分组并 note 降级原因 (index.js:77-90、index.js:77-79)；任务组装后 `agenticArticles` 开启则经 `markBigAgenticTasks` 打 `bigTier` 标记交 `startAgenticRun`（index.js:806-835），否则 `prepareArticleTasks` 单轮装填交 `startBatchChatRun`（index.js:2063-2079）；agentic 结果失败严格过半且未退回过时只重排失败篇走单轮重跑一次（index.js:79-117）；stale 路径另有 `symbolIncremental` 符号级过滤（`loadSnapshot`+`filterStaleTasks`，index.js:21-41；全部滤掉时刷新编译基线 index.js:2774-2780）与 `tickIndex` 的快照写入（index.js:2774-2798）。
7. **编译对象闸门链（1.2.0/1.2.1）**：所有提交入口（工具/面板 compile/自动调度）在 submit 处过三道闸——排除清单 (index.js:418-421) → worktree (index.js:418-425) → 空壳目录 (index.js:418-424)；面板 jobs/repos 端点再按 `isDeadCompileTarget` 过滤历史遗留条目（index.js:418、index.js:1587），启动时一次性清理残留 job 并 `forgetRepo` (index.js:1587-1608)；autoScan 扫描同样跳过 (index.js:1587-1591)。
