## Overview

`wiki-generation` 指 `@local/dsh-codewiki` 插件把一个代码仓库转化为结构化 CodeWiki 文档（`WIKI_PATHS` (`index.js:36`) 即 `<repo>/.codewiki/` 与 `CodeWiki.md`，随仓库提交共享）的端到端编译过程。入口工具 `codewiki_generate` 由 `generateToolDefinition` (`index.js:2611`) 定义：纯提交制——`normalizeCwd` (`index.js:40-45`) 归一路径、`runCw` (`index.js:142-167`) 跑 `cw status` 判态、按判态预构建任务后经 `submit` (`index.js:2492-2577`) 交给宿主常驻编排服务 `createJobService` (`index.js:1541-2604`) 即返回，工具路径零 LLM 调用、零子代理、不委托发起会话的主模型。服务在 `tick` (`index.js:2404-2490`) 里以 `TICK_MS` (`index.js:1163`) 默认 10s 的节拍推进阶段机 queued → articles → crosscut →（超预算拆分时 compose）→ review → index → commit → done，阶段分发表是 `STAGE_HANDLER` (`index.js:2395-2402`)；0.10.7 起无规划阶段，模块清单由 `localPlan` (`index.js:832-845`) 按顶层目录本地分组。全部模型环节在插件内的后台并发池 `runRealtimeTasks` (`index.js:449-508`) 完成，唯一模型通道是 `llmChat` (`index.js:392-417`) 包装的宿主 llm 服务（0.10.1 起无内置直连，插件不保存任何密钥）：普通档默认 `DEFAULT_BATCH_PROVIDER` (`index.js:26`)/`DEFAULT_BATCH_MODEL` (`index.js:27`)（workbuddy/hy3，192k 上下文，单请求输入预算 `BATCH_TOKEN_BUDGET` (`index.js:521`)=110k）；110k–420k 输入自动升大档——默认 `DEFAULT_BIG_PROVIDER` (`index.js:30`)/`DEFAULT_BIG_MODEL` (`index.js:31`)（volces-ark/glm-5.3-flash，512k 上下文），预算 `DEFAULT_BIG_TOKEN_BUDGET` (`index.js:33`)=420k，大档任务与普通档任务分池限流（`bigConcurrency` (`index.js:63`) 默认 0=跟随默认档并发，分池逻辑 `index.js:36-54`）；只有单文件连大档都装不下才转会话通道兜底（`dispatchSessionTasks` (`index.js:1870-1904`)，超时 `SESSION_TASK_TIMEOUT_MS` (`index.js:1167`) 默认 30 分钟按失败处理）。0.10.11 起产物提交是阶段机里的显式一步：`tickIndex` (`index.js:2345-2375`) 末尾在有产物且 `autoCommit` 开启时移交 commit 阶段，`tickCommit` (`index.js:2377-2393`) 执行 `autoCommitWiki` (`index.js:3406-3488`) 的「主题分支提交 → 合并回原分支」后才置 done 并唤醒；提交状态由 `autoCommitState` (`index.js:1517-1522`) 判定 committed/no-changes/pending 三态，`wakeCompileSession` (`index.js:1524-1539`) 在已提交/无改动时完全静默。0.11.0 起并行项目推进（`parallelProjects` (`index.js:65`)，关串行后上限 1–4）与编译会话记录（`SESSIONS_DIR` (`index.js:1179`)，保留 24h）可用；0.12.0 起 linked git worktree 目录拒绝编译（`detectLinkedWorktree` (`index.js:289-305`)）；0.12.1 起「扫不出源码」的空壳目录同样拒绝并从面板过滤（`isDeadCompileTarget` 1. **配置与理解**：
   - 工具语义与关键行为：README.md:15-22（提交制、scope=auto/full/stale 语义、并发默认 2、单项目串行、单篇失败只记账不中断、全部失败不刷新基线）；0.12.1 变更全文见 CHANGELOG.md:3-23。
